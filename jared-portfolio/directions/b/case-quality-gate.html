The 54,000-output read before a launch call

A new AI recap looked great in the demo. Before anyone turned it on, I read what it would really produce for our clients. Then I recommended a staged rollout behind an explicit quality gate, not a full launch.

  • WhereA B2B coaching platform, 3,600+ active clients
  • My rolePM for the AI and coaching-intelligence track
  • The read54,000+ outputs, 3,400+ clients

Context

The platform already ran an AI summarization pipeline in production. The next item on the roadmap I own was a new AI recap capability built on top of it. The launch call was mine to recommend.

Problem

Demos are picked from good inputs. Real clients aren't tidy. Some log a lot, some barely log at all, some have history that doesn't line up. A recap that reads well for the typical client can be wrong or thin for the long tail.

Coaching runs on trust, and a confident, wrong recap costs more than a missing one. So the real question was: is it good enough for every client we'd show it to, and what happens when it isn't?

Decisions

Size it from production, not the demo

I pulled what the recap would produce across the real base, 54,000+ outputs from 3,400+ clients, querying production myself.

Trade-off: slower than a demo review, but the long tail shows up before launch instead of after.

Write the bar down first

I defined "good enough" as an explicit quality gate, so the decision rested on a written standard rather than on how the last few examples felt.

Trade-off: a strict gate holds back some fine outputs. A held-back recap is easier to explain than a wrong one.

Stage it instead of launching to everyone

Start where outputs cleared the gate, widen only as quality held.

Trade-off: slower to full reach, but reversible, and every step is measured on real usage.

Try the bench

Pick a synthetic recap, tick the checks it passes, and see where a gate like this would route it. The drafts and the checks are illustrative, not the real rubric.

Outcome

My recommendation was a staged rollout behind an explicit quality gate rather than a full launch. This page is about that decision. Rollout results aren't included here.

The same question came back when the model behind our production summaries was retired. I led the replacement and the fallback plan with engineering, and the bar was the same: is the new output good enough, and what happens when it isn't?

What I'd do next

Make the gate cheap to rerun: an automated scorer, checked against human reads, so every model or prompt change passes the same bar before it reaches a client. Then track what slips through after launch and tune the bar on that evidence.

The public version is underway: Gatekeeper, the same idea for AI-drafted lifecycle messages, on synthetic data.
